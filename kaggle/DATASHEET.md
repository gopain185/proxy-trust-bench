# Proxy Selection Simulations

Simulated "competition seasons" in which a competitor picks an offline proxy (an out-of-fold score, a cut of it, a
holdout) by its correlation with a few public leaderboard scores, then ranks the next submissions by it. Every
quantity has a known ground truth, so the data shows how often that choice is right and what it costs.

## Provenance and generation

Fully synthetic; no real competition data. Generated by `python -m proxytrust.run` from the proxy-trust-bench
repository (code MIT, embedded in the companion notebook). Each cell of the grid uses its own NumPy seed
(`default_rng(1000 + cell index)`), so the files are exactly reproducible.

Model: a pool of 300 configurations with latent true quality `q ~ N(0, 1)`; proxy
`p_k = rho_k q + sqrt(1 - rho_k^2) (sqrt(c) s + sqrt(1 - c) e_k)`; public leaderboard `L = r q + sqrt(1 - r^2) u`.
Phase 1 submits `n1` configurations (`random` or the `top` by the mean of the proxies); phase 2 submits the top 5 of
the rest by the strategy `select` (best phase-1 Spearman), `mean` (mean of standardised proxies) or `oracle` (the
truly best single proxy).

## Files

`runs.csv`: 180,000 rows, one per simulated season.

| column | meaning |
| --- | --- |
| scenario | proxy set: `spread` (rho 0.40/0.55/0.70/0.85), `close` (0.60/0.65/0.70/0.75), `equal` (0.70 x 4) |
| c | share of proxy error common to all proxies (0 or 0.8) |
| r | correlation of the leaderboard with the true quality (0.5, 0.7, 0.9) |
| n1 | number of phase-1 submissions (5, 10, 15, 20, 40) |
| design | how phase 1 was chosen: `random` or `top` |
| rep | season index within the cell (0-999) |
| sel | index of the proxy with the best phase-1 Spearman |
| hit | whether that proxy is a truly best one (empty for `equal`, where it is undefined) |
| rho1_sel, rho1_best | phase-1 Spearman of the selected proxy and of the truly best proxy |
| q1_mean | mean true quality of the phase-1 submissions |
| q2_select, q2_mean, q2_oracle | mean true quality of the 5 phase-2 submissions under each strategy |
| q2max_select, q2max_mean, q2max_oracle | best true quality among those 5 |
| rho2_sel | Spearman of the selected proxy with the leaderboard on its own 5 phase-2 picks |

`summary.csv`: 180 rows, one per grid cell, with the means of the above, plus:

| column | meaning |
| --- | --- |
| rho_true_sel | the population Spearman of the selected proxy with the leaderboard |
| optimism | `rho1_sel - rho_true_sel` |
| regret_select, regret_mean | `q2_oracle` minus the strategy's `q2` |

`DATASHEET.md`: this file.

## Intended use

Teaching and planning: how many leaderboard points you need before trusting a proxy-vs-LB correlation, and why a
low correlation among your top submissions is expected.

## Known limitations

- The model is Gaussian and linear, each proxy has a fixed correlation with the truth, and a proxy has no bias of
  the kind a leaderboard calibration is meant to catch.
- Leaderboard noise is independent across submissions; a real public split is fixed, so its errors are correlated
  for similar submissions.
- Phase 2 always has 5 submissions, and the pool always has 300 configurations.
